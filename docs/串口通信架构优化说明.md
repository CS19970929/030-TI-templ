# 串口通信架构优化说明

## 1. 本次目标

本次优化的目标不是单纯“能通讯”，而是把当前项目的串口通信层整理成更稳定、也更容易迁移到旧项目的结构。

优化目标如下：

1. 发送改为中断发送，避免主循环阻塞轮询。
2. 接收中断只做收字节，不在中断里做 CRC、协议处理和业务寄存器操作。
3. 主循环负责判帧、协议解析、组应答。
4. 增加接收超时，避免半包长期卡死状态机。
5. 保留现有 Modbus 与 P12 协议行为，不替换业务层。

## 2. 调整后的分层

### 2.1 中断层

`USARTx_IRQHandler` 现在负责三类事情：

1. 串口异常检测与清错
2. `RXNE` 收单字节
3. `TXE/TC` 发送中断驱动

中断层不再做：

1. CRC 校验
2. Modbus 命令解析
3. P12 业务应答生成
4. 寄存器读写业务处理

### 2.2 主循环层

主循环中的 `App_CommonUpperSCI()` 负责：

1. 根据当前缓冲区内容判定是否已形成完整帧
2. 根据协议类型做 Modbus / P12 解析
3. 生成应答数据
4. 启动发送
5. 处理接收超时和发送节流

这样做的好处是：

1. 中断路径更短，现场鲁棒性更高
2. 协议逻辑集中在主循环，更容易调试
3. 后续增加协议或继续拆模块时，改动边界更清楚

## 3. 当前状态机

仍沿用原有的 `RS485MSG.csr` 状态值：

1. `RS485_STA_IDLE`
2. `RS485_STA_RX_COMPLETE`
3. `RS485_STA_RX_OK`
4. `RS485_STA_TX_COMPLETE`

但内部职责已经调整：

1. `IDLE` 表示接收中或空闲中，由主循环判断是否已收满一帧
2. `RX_COMPLETE` 表示一帧已确认完整，等待主循环解析
3. `RX_OK` 表示已经完成解析，等待组包和启动发送
4. `TX_COMPLETE` 表示正在等待发送完成或发送已结束待收尾

## 4. 超时机制

本次增加了 `RX` 超时字段：

1. `u8RxTimeoutTick`

处理逻辑：

1. 中断每收到 1 个字节就清零超时计数
2. 主循环按 10ms 节拍递增
3. 如果还在接收态但一直凑不成完整帧，超时后直接丢弃当前帧并恢复接收

这样可以解决：

1. 半包卡死
2. 干扰字节把后续正常数据拖入错误帧
3. 上位机异常中断发送后从机长时间不恢复

## 5. 发送机制

本次发送改成：

1. `TXE` 中断装载下一个字节
2. `TC` 中断确认最后一个字节真正发完

同时保留原工程对长包的节流逻辑：

1. 当发送到第 `19/39/59` 字节后，临时关闭 `TXE`
2. 主循环按 10ms 节拍恢复 `TXE`

这样做是为了尽量保持原项目的发送节奏，不直接改变现场链路习惯。

## 6. 复用方式

当前 `SCI1` / `SCI2` 继续保留各自薄包装函数，但核心逻辑已经收敛到公共函数：

1. `Sci_CommonUpper_FaultChk`
2. `Sci_CommonUpper_Rx_Deal`
3. `Sci_CommonUpper_Tx_Deal`
4. `Sci_CommonUpper_TxIrq_Deal`
5. `App_CommonUpperSCI`

因此迁移到旧项目时，优先迁移这几类公共函数，再保留每个串口自己的：

1. 串口实例
2. 错误计数
3. 发送完成标志
4. 初始化 GPIO / USART 差异

## 7. 当前边界

本次已经完成的是：

1. 中断发送
2. 主循环判帧与解析
3. 接收超时
4. SCI1 / SCI2 公共化

本次还没有继续展开的是：

1. 更细的 1ms 级帧间超时
2. 环形缓冲区
3. DMA 发送/接收
4. 串口层和协议层拆成独立源文件

如果后续还要进一步演进，建议顺序是：

1. 先做实机回归，确认当前时序在现场稳定
2. 再考虑把协议判帧和串口驱动拆成两个模块
3. 最后再考虑 DMA 或统一端口表驱动
